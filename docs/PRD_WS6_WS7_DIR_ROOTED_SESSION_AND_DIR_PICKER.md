# PRD — WS-6/WS-7：在项目（任意目录）里开新任务 + 宿主目录选择器

> **状态**：已定案（grill 2026-09-12，用户逐项拍板）。
> **决策依据**：ADR-0027（会话 `cwd` 开放任意已存在目录）、ADR-0028（宿主只读目录列举端点）。
> **读者**：后续接手的 AI / 集成 AI。本文与两张票（WS-6、WS-7）配套：票里的 AC 自含可施工，
> 本文提供完整契约矩阵与理由；两者冲突时**以本文 + ADR 为准**并回报 Gap。
> **词汇**：见根目录 `CONTEXT.md`（Workspace / Project / Directory-rooted Session）。

---

## 0. 一句话

让用户能（a）**在一个目录/项目里直接开新任务**（会话的工作目录就是那个真实目录，而不是
Harness 的 scratch 目录），（b）**像桌面应用那样点选目录**而不是手填绝对路径。

## 1. Problem Statement（用户视角）

1. 我注册了一个项目（我的真实代码目录），但项目里**没有任何"开始任务"的入口**；从顶部 + 新建的
   会话永远落在"未分组"，而且**永远加不进项目**（后端拒绝："目录不属于项目"）。项目分组对我这个
   纯界面用户来说整个是摆设。（实测：2026-09-12，证据见 ADR-0027 Context。）
2. 「新建项目」要我自己敲一个绝对路径。桌面应用（ZCode）都是弹一个文件夹窗口让我点选。
   浏览器拿不到真实路径是平台事实，但这不该由我来体谅——产品应该给我一个能点选的目录浏览器。

## 2. Solution（用户视角）

- 在**项目行**（含空项目）和**空项目状态**里出现「在此项目中新建任务」；点开后是一个**确认面**：
  明示"Agent 将直接读写该目录：<路径>"，旁边可选权限档（默认 workspace-write），填任务、点开始
  ——会话直接诞生在这个目录里，并自动出现在该项目的分组下。
- 「新建项目」对话框内嵌**目录浏览器**：从盘符/根一路点进去，也可以直接粘贴路径回车跳转；
  「选择此目录」回填表单。手填路径仍然可用（后备）。
- 服务端只新增两条能力：会话创建接受 `cwd`（已存在的绝对目录）；一个**只读**的宿主目录列举端点。

## 3. User Stories

1. 作为用户，我想在某个项目行上点「在此项目中新建任务」，这样我不用先去未分组里碰运气找 cwd 匹配的会话。
2. 作为用户，我想在确认面上看到"Agent 将直接读写该目录：<绝对路径>"，这样我不会误把 agent 放进错误的目录。
3. 作为用户，我想在同一个确认面里选权限档（默认 workspace-write），这样对敏感目录我可以手动降级成逐次审批。
4. 作为用户，我想让这样创建的会话**自动出现在该项目的分组下**，这样我不需要再做一次"加入项目"。
5. 作为用户，我想在空项目上看到同样的入口（而不是现在那句"去未分组找 cwd 匹配的会话"），这样空项目不会是死胡同。
6. 作为用户，我想在「新建项目」时点选盘符 → 逐级进入目录 → 「选择此目录」，这样我不用背路径。
7. 作为用户，我也想直接**粘贴路径回车**让浏览器跳过去，这样对熟悉的目录手填更快。
8. 作为用户，路径敲错时我想看到**具体原因**（不存在 / 是文件 / 无权限），这样我能自己修正。
9. 作为用户，注册项目成功后，我想看到"已归入 N 个 cwd 匹配的历史会话"，这样我立刻知道分组生效了。
10. 作为用户，我想让带 cwd 创建的会话的目录**自动注册为项目**（若尚未注册），这样"在任意目录开任务"不会产生无归属的孤儿会话。
11. 作为用户（CLI/脚本使用者），我想让既有的 `workspace`（单段名）用法原样工作，这样我的脚本不被破坏。
12. 作为用户，我想让 `workspace` 和 `cwd` 同时填时得到**明确的二选一报错**，这样不会有含糊的优先级。
13. 作为用户，目录浏览到无权限的目录时，我想看到 403 的明确提示，而不是"空列表"或报错崩溃。
14. 作为用户，目录条目极多时（如 C:\ 下成千上万项）我想看到截断标记，这样我知道列表不完整而不是"就这些"。
15. 作为用户，我想让「新目录开任务」创建出的会话和普通会话一样可恢复 / 可分叉 / 可回放，这样目录会话不是二等公民。
16. 作为用户，项目被软删除后，我再「在此项目中新建任务」时想得到明确错误（项目不存在/目录不存在），而不是静默重建。

## 4. Implementation Decisions（契约矩阵——施工以本节为准）

### 4.1 `POST /api/sessions` 增量（WS-6 后端，ADR-0027）

请求体新增可选字段 **`cwd: str | None = None`**（既有字段全部不动；`workspace: str | None` 保留）。

**校验与解析顺序**（顺序本身是契约，测试逐条断言 detail）：

| # | 输入 | 结果 |
| --- | --- | --- |
| 1 | `workspace` 与 `cwd` 同时非空 | 422，detail=`workspace 与 cwd 只能二选一` |
| 2 | `cwd` 非绝对路径 | 422，detail=`cwd 必须是绝对路径：'<原值>'` |
| 3 | `cwd` 指向不存在路径 | 422，detail=`目录不存在：<规范路径>`（**不代创建**） |
| 4 | `cwd` 存在但不是目录 | 422，detail=`不是目录：<规范路径>` |
| 5 | `cwd` 合法 | `Path.resolve()`（realpath 语义）→ 作为会话 workspace root → **自动入组**（见下） |
| 6 | 都缺省 | 现行为逐字节不变（`workspaces_root/<session_id>`） |

**自动入组（幂等）**：规范化路径若尚未注册 → `create` 进项目注册表（title = 目录末段名）；
然后 attach 该会话（已在账本则 no-op）。两条入口（`POST /api/projects` 与"带 cwd 建会话"）
共用同一注册/attach 机制，**不会**造出重复项目条目。

**事件**：`session/started.data.cwd` = 规范化后的绝对路径（#151 的既有机制，无新事件类型）。
**响应**：create 端点的响应是 SSE 事件流，无新增响应字段。

**权限**：不新增权限档、不新增路径检查（ADR-0027 Security：policy 是工具级闸，新增"路径级
workspace-write"会造出两种语义；若将来要，另立 ADR）。默认档仍 `workspace-write + auto-approve`，
请求体既有 `permission_mode` 字段照常生效（前端确认面上可改，见 4.3）。

### 4.2 `POST /api/projects` 增量（WS-6 后端，Q6 定案）

- 成功响应**新增字段** `sessions_attached: int`：本次调用**新** attach 进来的会话数（幂等重放时为 0）。
- 行为：注册成功（含幂等命中既有项目）后，把**所有 cwd 规范路径等于本项目规范路径**的既有会话
  attach 进账本。软删除→重新注册的闭环由此补齐（#155 软删除时会 detach 全部成员）。
- 判定在后端做（它知道每个会话的 cwd）；前端**不猜**。

### 4.3 「在此项目中新建任务」入口（WS-6 前端）

- 入口两处：项目行 kebab 菜单新增第一项「在此项目中新建任务」；空项目的占位区把现有那句
  "去未分组找 cwd 匹配的会话"替换为**该入口按钮**（旧文案的语义已被本功能取代）。
- 点击打开**任务确认面**（Radix Dialog，复用现有浮层材质），内容自上而下：
  1. 路径明示行：`Agent 将直接读写该目录：<项目规范路径>`（强视觉，Q2=C 的硬要求）；
  2. 权限档三选（默认 `workspace-write`；复用既有三档语义，不发明新档）；
  3. 任务输入框（多行）+「开始任务」按钮（空任务禁用）。
- 提交 = `POST /api/sessions { task, cwd: <项目路径>, permission_mode }` → 走既有 SSE 流接线
  （选中该会话、跟随流）。创建失败（如项目目录已被移走 → 422）时错误**留在确认面**可重试。
- **坑点（默认档必须不发 `permission_mode`）**：后端语义是"显式传了非 DANGER 档 → 切交互式
  审批"（`service.create_and_launch` 的 `permission_mode_explicit` 判定 + `session/approval.py`
  三分支；真机实测：不传该字段 → 工具直接执行，`tool/result` 出现在流里无需审批）。所以
  确认面必须：用户**留在默认档**时 payload **不含** `permission_mode`（= 默认
  workspace-write + auto-approve）；只有用户主动改档才发该字段（改档 = 要逐次审批，这正是
  交互式的意义）。既有 `web/src/lib/api.ts` 的参数映射已是这个形状
  （`p.permission_mode ? ['permission_mode', p.permission_mode] : null`），照用即可——
  **别为了"显式"把默认档也塞进 payload**，那会让每个工具调用都弹审批卡。
- 项目 `status=missing-dir` 时入口照常出现，点击后由后端 422 明示（前端不预判）。
- 未分组会话既有的「加入项目…」保留不动（历史会话仍靠它归组）。

### 4.4 `GET /api/host/dirs`（WS-7 后端，ADR-0028）

查询参数 `path: str | None`。响应 200 形状：

```json
{
  "path": "D:\\data",          // 规范化后的当前目录；path 缺省时为根 pseudo 条目
  "parent": "D:\\",            // 上一级；根为 null
  "truncated": false,          // 子目录数超过 500 时 true，且 entries 被截到 500
  "entries": [ { "name": "repos", "path": "D:\\data\\repos" } ]   // 仅目录，按 name 排序
}
```

- `path` 缺省 → 列**根**：Windows = 存在的盘符根（`C:\`…，大小写与系统一致），POSIX = `["/"]`；
  此时 `parent` 为 `null`。根枚举做成**可注入 provider**（生产实现 + 测试假根），不在测试里
  真扫盘符。
- 错误矩阵（**不许冒成 500**）：`path` 非绝对 → 422 `path 必须是绝对路径`；不存在 → 404
  `目录不存在：<规范路径>`；是文件 → 422 `不是目录：<规范路径>`；`PermissionError` → 403
  `无权限访问：<规范路径>`。
- 闸：`require_trusted_origin`（与项目/记忆端点同一份实现，不复制）。
- 不做：文件列举、内容读取、搜索/通配、写语义、symlink 展开（symlink 目录照列一个条目，
  进入时按真实目标解析，仍是一层列举）。

### 4.5 「新建项目」内嵌目录浏览器（WS-7 前端）

- 对话框结构：既有表单（路径输入 + 项目名）在上，下方内嵌浏览器：当前路径条（可编辑，
  回车=跳转）+「向上」+ 子目录列表（点选进入；当前目录高亮）+「选择此目录」。
- **双向同步**：浏览器点选/跳转 → 回填路径输入框；手改输入框回车 → 浏览器跳转。加载/错误
  状态就地显示（403/404 用后端 detail）。
- 浏览器组件做成**可复用**：「在此项目中新建任务」若未来要支持"浏览到新目录"可直接复用
  （本期不做，见 Out of Scope）。
- 真实请求形状见 4.4；e2e 用状态 mock（`routeApi` 增加 `/api/host/dirs` 分支 + 可编程的假目录树）。

### 4.6 词汇与文档

- `started.data.cwd`、`SessionSummary.workspace`、项目账本语义不变；`workspaces_root` 从

## 5. Testing Decisions

**原则**：只测外部行为（HTTP 契约 / UI 可见行为），不测内部函数；优先既有 seam，不新增 seam。

- **后端**（最高 seam = HTTP 契约测试，真实 app + 临时目录，先例
  `tests/web/test_projects_api.py` / `test_memory_api.py`）：
  - WS-6：4.1 的 6 行校验矩阵逐条断言 detail；cwd 合法路径 → `started.data.cwd` 等于规范化路径、
    项目注册表出现该目录、会话已 attach；幂等（同 cwd 二次创建不重复建项目）；`workspace` 名字
    旧路径回归不变；`POST /api/projects` 的 `sessions_attached`（0 / N / 幂等重放 0）。
  - WS-7：4.4 的错误矩阵逐条；一层列举 + 排序 + 截断标记；根枚举用注入的假 provider；
    trusted-origin 闸（403 来源）与既有端点同款用例。
- **前端**（vitest 纯函数 + e2e 状态 mock，先例 `e2e/r-project-groups.spec.ts` / `s-memories.spec.ts`）：
  - WS-6 e2e：项目菜单出现新入口；确认面明示路径；提交后请求体带 `cwd` 与 `permission_mode`；
    新会话落在该项目分组下；422 错误留在确认面可重试；空项目的入口可用。
  - WS-7 e2e：mock 假目录树下点选导航 / 向上 / 粘贴跳转 / 双向同步 / 截断标记 / 403·404 文案；
    「选择此目录」回填表单后注册成功。
  - 真机车道：两票各跑一遍真后端 + 真浏览器（先例 `e2e-live/`）。

## 6. Out of Scope

- 路径级权限（写白名单 / deny 清单）——若需要，另立 ADR 演进 PermissionPolicy。
- 目录搜索 / 通配 / 文件浏览 / 隐藏目录开关。
- 存量 `workspaces_root/<uuid>` 会话的迁移或强制归组（ADR-0027 D4：接受现状）。
- 「浏览到任意新目录再开任务」（确认面里嵌浏览器）——本期入口只吃已注册项目的路径；
  浏览器组件按可复用实现，后续要放开是小增量。
- 非本机部署形态下的 FS 端点重评估（ADR-0028 Consequences 已记约束）。
- 上传 / 导入目录（zip / git clone）。

## 7. Further Notes

- 实施顺序（§14.9 一次一条分支）：WS-6 后端 → WS-6 前端 → WS-7 后端 → WS-7 前端；
  也可 WS-7 后端先行（与 WS-6 无依赖）。跨端票按 §14.12：两端齐备才关单。
- 兼容性承诺：不传新字段的调用方行为**逐字节不变**（CLI、既有 e2e、脚本）；旧 `workspace`
  名字语义长期保留（ADR-0027 D3）。
- 真机验收必须包含：在真实代码目录开任务并让 agent 读到该目录的文件（证明 cwd 真的生效）；
  确认面文案肉眼可见；权限档切到 read-only 时写操作确实被审批/拒绝。
- UI 文案是 AC 的一部分：「Agent 将直接读写该目录：<路径>」必须逐字出现（e2e 断言）。
