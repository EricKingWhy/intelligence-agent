## 为什么要审文档

这不是代码，是**交给集成 AI 的唯一执行指令**。文档写错的后果与代码 bug 同级：

- 写出一个**不存在的 Git ref** → 集成 AI 照抄 → 命令直接失败
- 写错**commit 数量 / 拓扑** → 集成 AI 误判合并范围
- 遗留**过期的"权威入口"** → 集成 AI 先读它，得到错误计数

这一轮审出 **1 处硬伤（命令必然失败）** 和 **1 处真事故（权威文档滞后 3 个 commit）**。

## Standards 轴结论

**事实数字全部准确** —— HEAD、`ahead 8 / behind 6`、merge-tree `ac73da9`、19 文件、
merge-base `c00f742`，逐条实测吻合。

### 硬伤 1：§5 步骤 4 引用了不存在的 ref

```text
文档原文：  git -C D:/intelligence-agent merge feat/frontend
实测：      git -C /d/intelligence-agent rev-parse feat/frontend
            → fatal: Needed a single revision
```

**成因**：上一版遗留的僵尸行。它**与同一文件 §1.1 / §9.7 自相矛盾**
（那两处明确说 main 侧只有 `origin/feat/frontend` 可解析）。

**更糟的是排序**：步骤 4 在步骤 5 的 `fetch` **之前**执行 →
照文档顺序走，第 4 步直接失败。

**修法**：删掉重复的步骤 4，把正确流程（fetch → merge-tree → merge）并入步骤 4，
后续步骤重编号为 1-7。

### 判断瑕疵 2：docs 计数三处不一致

`2 个 docs`（§1、§9.6）vs `3 个 docs`（§6），差异来自是否把 `CONTEXT.md` 算作 doc。
实测 main 侧改动 = `src/agent_harness/**`(6) + `CONTEXT.md`(1) + `docs/`(2)。

**修法**：三处统一写「`src/agent_harness/**`（6 文件）+ `CONTEXT.md` + `docs/` 下 2 个文件」，
消除歧义。

### 基线气味（judgement call）

同一事实在多处重复（merge-tree 哈希在 §2 与 §6 草稿；`8/6` 在 §1 与 §9）——
已知会漂移，故文档本身已加「以集成时实测为准」免责；**§6 是粘贴目标**，
若把过期哈希粘进 `PHASE_STATUS.md` 会永久留存。

## Spec 轴结论

这一轴更狠，除命中同一处 §5 硬伤外，还找出交接**缺口**：

### 缺口 1：预检脚本的时序未说明（**确证的真问题**）

`verify-before-merge.sh` 第 3 项断言「本地 HEAD == `origin/<branch>`」。
而文档步骤 2-3 会**在前端分支上 merge + 提交** → 本地 HEAD 必然超前 origin →
**此后跑预检必然 FAIL**。

文档未提示，集成 AI 会误判成「仓库坏了」。

**修法**：新增 **§5.1 时序说明**，明确「预检必须在先回后正之前；之后 FAIL 属预期」，
并在步骤 1 / 步骤 3 各加一行指针。

### 缺口 2：脚本只覆盖待合并侧

脚本硬编码要求 CWD = 前端仓库，**检查不了** `D:\intelligence-agent`。
文档未声明此边界。

**修法**：新增 **§5.2**，给出目标侧独立检查命令（`fsck` + `rev-parse main`），
并记录本轮实测结果（main 侧 `fsck` 干净、独立仓库、`main` = `ebb2d68`）。

### 缺口 3：FAIL 后无处置手册

原文只有「有任何 FAIL 先处理」。5 类 FAIL 的处置方式完全不同
（fetch / 提交 / 按 §14.7 解决冲突 / 人工确认重叠）。

**修法**：新增 **§5.3 FAIL 处置表**，按脚本输出的检查项分类给处置。

### 缺口 4：手验步骤无通过标准

原文只写「重点——第 N 轮标签逐轮递增」。未说明怎么触发、在哪看、失败了是否回滚。

**修法**：步骤 5 补通过标准（(a) 连发 ≥3 轮验递增；(b) 短/长目录下搜索框隐藏/显示），
并写明「(a) 失败则**不要 push**，回滚本次 merge」。

### 事故：`BATCH_DELIVERY` 自称权威却滞后 3 个 commit

```text
文档自称：本文件是本批次交付的【权威入口】
但它写的是：tip `eb999bc` / 5 个 commit / ahead 5
实测真相：  tip `b354896` / 8 个 commit / ahead 8
```

集成 AI 若先读它 → 得到**错误的合并范围**。

**修法**：同步 header、commit 表、拓扑表、收尾章节至 8 commit / `b354896` / `ac73da9`，
并加一行「本文件曾滞后，判断数量以 `git rev-list --count main..HEAD` 实测为准」，
外加 §四.1 三点-vs-两点 diff 的提醒。
