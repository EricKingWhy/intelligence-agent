## 1. 处置方式：一次性迁移（用户选定方案 ①）

脚本：`scripts/migrate_legacy_step_id.py`（幂等、默认 dry-run、自动备份）

重编号规则（与修复后 runtime 同一口径，见脚本 docstring）：

```
allocated = 0            已分配 turn 数（= 前端 turns.length）
run/started          →  anchor = allocated
user/message（非注入）→  allocated += 1
带 step_id 的事件     →  new = anchor + (raw − 本 run 首个 raw)
                        allocated = max(allocated, new)
```

**只改 `step_id`**：逐行处理，只有值真的变化的行才按 `JsonlSessionStore` 的同一序列化口径
重写，其余行逐字节保留（seq / type / data / 行序 / 键序均不动）；损坏行不解析也不改。

安全设计：
- `--apply` 前**逐文件备份**到 `<store 上级>/step-id-backup-<UTC 时间戳>/<session_id>/events.jsonl`
- 写入前复核**内容哈希**：规划之后文件被 append（服务在跑）→ 拒绝执行，绝不覆盖正在写入的会话
- 写临时文件 + `Path.replace` 原子替换
- 写盘前先做两项**不变量自校验**（失败则一行都不写）：① 迁移后无跨轮步号重叠；② 迁移幂等
