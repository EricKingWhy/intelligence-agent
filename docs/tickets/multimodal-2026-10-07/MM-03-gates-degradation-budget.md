# MM-03 · 门禁与降级：上限、非视觉模型、预算计入

**目标仓库**：intelligence-agent-backend（config / 发送端点 / derive 投影 / token 估算）。
**类型/优先级**：P0。**Parent**：#821。
**Blocked by**：#823（MM-02）。

## What to build

图太大或太多时，用户立刻看到明确原因（哪个文件、超了什么），而不是等发送失败或静默变形；
所选模型不支持视觉时，客户端入口被禁用、服务端权威拒绝、**即使入口被绕过**也会在投影里变成
一句明确的「图已被省略」文本；图片被计入 token 预算，不会因为「看不见的图」撑爆上下文窗口。

## Acceptance criteria

- [ ] 超数量 / 超单消息总字节 / 超像素 / 超边长 → 明确 413 或 422，且**不落事件、不留存储残留**。
- [ ] 归一化目标生效（2048² 像素 / 8192px 边长 / 4 MiB）：在可救范围内的超限图片被缩放而不是直接拒绝；
      不可救的明确拒绝并说明原因。
- [ ] 模型目录 API 暴露 `supports_vision`，客户端可据此做入口门禁（此前该字段是死元数据）。
- [ ] 发送端点在模型不支持视觉时返回 422（权威校验，不信任客户端）。
- [ ] `derive_messages` 在模型不支持视觉时把引用替换为**固定文案**占位符（逐字可测），
      不静默丢弃、不中断本轮。
- [ ] 入口门禁 + 投影降级构成双保险：入口被绕过（例如发送后 fallback 到非视觉模型）时仍降级而非报错。
- [ ] 图片按 Provider 近似公式计入 token 估算与上下文压力，口径在代码与文档中显式记录；
      不出现「图不计费导致 hard guard 失守」。
- [ ] 每条上限都有失败路径测试；视觉/非视觉两条投影分支都有测试。
- [ ] 无附件的纯文本链路回归全绿。

## 复用与来源

- 上限默认值与归一化档位取 DSH（MIT，commit `5badb150`）`ImageAttachmentLimits` 与 `normalization.ts`。
- 「后端为权威、把配置下发前端」的镜像模式参考 Open WebUI / LibreChat（调研报告 §2.4）。
- 非视觉模型下的占位符语义逐字取自 Pi（MIT），便于跨端核对。

## 明确不做

客户端侧的门禁 UI（MM-04 / MM-06 / MM-07 各自实现）；模型 fallback 策略本身（既有机制，不改）。
