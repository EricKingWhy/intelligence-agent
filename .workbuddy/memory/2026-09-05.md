## ⚠️ 重要环境异常：git ref 闪烁（跨会话复发）

- 症状：sandbox 执行的 `git commit` 报告成功，但 `refs/heads/feat/*` loose ref 随后消失（worktree HEAD 悬空，git status 显示"No commits yet"+全文件幻影 staged）。提交对象与 reflog 始终完好。frontend 与 backend worktree 都中招，各发生 2 次。
- 特征指纹：reflog 里出现无消息的 `0000000→<sha>` 重建条目 = ref 曾被删除后重建。
- 根因（推断）：多 AI 会话 × 双 Git 工具链（`D:\DevTools\Git` vs workbuddy PortableGit）× 沙箱对 worktree 外 `.git` 路径（本 worktree 的 gitdir 在 `D:\intelligence-agent\.git\worktrees\`）写入拦截。ref 更新的 lockfile+rename 产物被丢弃；对象库不受影响。
- **应对协议（本会话验证有效）**：①commit 后同一命令内 `git log -1` 验证；②缺失则 `mkdir -p .git/refs/heads/feat && git rev-parse <sha> > .git/refs/heads/feat/<branch>` 重建；③立即 push（credential.helper=manager，`helper-selector` GUI 会在非交互环境挂起被 SIGTERM）；④以远端 `ls-remote` 为最终事实源。
- push 的另一坑：`git push` 偶发 SIGTERM 但实际已成功——push 后必须 ls-remote 确认，不要凭退出码重推。
- backend 侧另见：裸 `git status` 卡死而 `--untracked-files=no` 秒过（疑双工具链 index 格式互相刷新 + 大目录 untracked 扫描）。
- 并行风险：另一 AI 会话（CSP 字体自托管）曾在本 worktree 直接提交 `744787f`（违反 AGENTS.md §13 每会话独立 worktree 约定）——动手前务必先 `git log` + `git status` 核对他人未提交工作。
