## Design Specificity 判定：为这个产品而作，但只做到 70%

有产品性格：Run Pulse 生命体征系统（icon+色相+文字+呼吸辉光+秒数+token 计量）、Trace Ladder 渐进披露（四档密度 × L0-L2 展开 × Main↔Inspector 联动）、终端块「内容里的另一块屏幕」材质。
任意 dev tool 可替换：顶栏/Rail/Inspector 共 11 个无标签 icon 按钮、无分组的命令面板、通用 chat 模板的会话列表。
最刺眼落差：产品最独特的「审批危险操作」时刻恰是设计最潦草的表面——性格在「观察」侧强，「决断」侧缺位。

**detector（deterministic）**：4 findings，同一 rule `side-tab`（>1px 彩色单侧边条）：app.css:1859 `.deleg-summary`(2px accent 34%)、:2366 `.approval-card`(3px warning)、:2444 `.approval-error`(2px destructive)、:4157 `.reasoning-text`(2px accent 32%)。逐条核实非误报，均有注释声明刻意；是否整改属设计决策。与 LLM 审查的交叉：detector 未覆盖 A 发现的材质违例（glass+辉光），A 也未点名 side-tab 模式——两侧互补。

## 总体印象

工程纪律高于平均的 Linear 系暗色工具，冻结决策真的长在代码里。最大的机会不在「再加东西」，而在三件事：把最高危的审批时刻做成配得上它的交互、把 75% 的微字号雾换成有节奏的排版层级、把 Inspector 从「粉色等宽字列表」升级成有结构的运行时间线。

## 做对了的（保持不动）

1. **Run Pulse 状态系统**：三通道（icon+色相+文字）+ 呼吸辉光 + 真实秒数 + token 计量 + 「等待模型」诚实旁注，中断/失败分色域。产品签名。
2. **渐进披露梯子**：密度四档全局默认 + 单节点 override + 折叠摘要行「已折叠 · N 工具 · M 轮 · 时长」+ 输出 8000 字符尾窗 + 「前 N 字符已省略」。视图裁剪 ≠ 数据丢弃贯穿。
3. **材质与 token 纪律**：实心面板 + 1px 边 + 亮度分层、玻璃严格限浮层、亮色单点维护、终端块跨主题恒定。正文行宽 78ch / 行高 1.7 实测达标；数字 tabular-nums 全覆盖；focus-visible 双环存在。

## Priority Issues

### P0 — 审批时刻整体失格
- **What**：`ApprovalCard` 直出转义 JSON（content 里字面 `\n`）；description/reason 字段后端给了但前端**根本没渲染**（B 实测 DOM 确认）；无 diff、无自动拒绝倒计时、无键盘快捷键、无焦点移入/aria-live；pending 期间 Composer 照常可输入；卡片视觉强度（amber 淡染）低于任何一条横幅。
- **Why**：这是产品唯一「界面替用户承担后果」的时刻，认知负荷 / 无障碍 / 错误预防三线在此同时失败（工作记忆项要求用户从转义串中段读出 rsync 目标）。
- **Fix**：path 一行置顶（mono、可复制）+ 内容区未转义 diff（复用 ToolCard 的 DiffBlock）；`role="alertdialog"` + 焦点移入；`Ctrl/⌘+⏎` 批准、`Ctrl/⌘+⌫` 拒绝并标注在按钮上；展示 fail-closed 倒计时（后端 300s 语义，UI 待确认字段）；pending 期间 Composer 置灰显示「等待审批」。
- 命令：`clarify` + `harden`（diff 部分属 `layout`）

### P1 — 微字号雾 + 低对比三级文本（B 实测确认）
- **What**：`font-size:10px`×30 处 + `--text-xs`(11px)×98 处 ≈ 75% 文字声明；`--text-tertiary` 实测对比度：暗 3.96-4.09、**亮 2.65-2.70**（AA 需 4.5），恰用在最小的 11px 字上（session meta、tl-seq、placeholder 亮 2.76）；亮色 accent 作 11px 事件名实测 **3.15**、亮色审批工具名 3.04。
- **Why**：层级靠透明度而非字号节奏建立，整屏缺「先看哪」的指令；最小字 × 最低对比是最差组合。
- **Fix**：元数据下限 11→12px；`--text-tertiary` 暗 0.42→0.52、亮同步提至 ~0.55（§15 双块同步）；事件名/审批工具名换中性 mono 色或限缩到 ≥14px；亮色 accent 文字用途限缩。
- 命令：`typeset` + `colorize`

### P1 — Inspector 时间线结构失明
- **What**：19 行事件平铺跨 2 个 run 无分组头；过滤行 5 个 icon 无标签无计数；头标 `run-2` vs 全会话列表矛盾。
- **Why**：Inspector 是产品名来源，却是唯一没编辑过信息结构的列表；事故现场需要「第 2 个 run 里发生了什么」。
- **Fix**：run 分隔行（序号+状态+起止+事件数）；过滤 icon → icon+计数 chip；头标与列表范围对齐。
- 命令：`layout` + `clarify`

### P2 — 真实数据形状下的信任裂缝
- **What**：未知事件摘要直出 `JSON.stringify().slice(0,40)`（`projection.ts:184`）；session/forked 误入未知分支（`projection.ts:785` 注释自认）；<50ms 显示「1ms」、reasoning「持续了 0 秒」。
- **Why**：观察工具的全部价值是「看到的可信」；三个「0/1ms/未知」同屏，用户对每处数字生疑。
- **Fix**：未知事件只显 type + 计数，payload 留给 L2；补 forked 分类；<50ms 显 `<50ms`，0 秒省略时长段。
- 命令：`clarify` + `harden`

### P2 — Rail 空态死胡同指路
- **What**：`SessionList.tsx:381`「右上角的『新建项目』」指向两个 icon-only 按钮，全 Rail 无文字标签。
- **Why**：空态是转化率最高的教学时刻，指路指到不存在的文字实体，项目分组核心入口被藏没。
- **Fix**：空态下 Rail 头部按钮展开为「新建项目」实心 + 「新会话」描边，或提示内联「注册项目目录 →」行动链接。
- 命令：`clarify`

3. 「紧凑/均衡/详细/Raw」三中一英；palette「切换到Raw」无 CJK 间距。
4. palette hint 列四种语义混一列（目标/方向/状态/序号）。
5. Split/Preview 空架子占一行 toolbar（诚实但每屏付费）。
6. 两套相近「已完成」胶囊（run-pulse vs run-badge）易混淆。
7. detector 4 处 side-tab 左条：accent 两条是克制的签名语言可留；approval 3px warning 条与 glass 材质冲突一起重做。

## 挑衅性问题

1. 若把 Inspector 整列粉色事件名换灰，0.5 秒内还能认出这是「Agent Harness Inspector」吗？认不出的话，accent 承担的是品牌还是墙纸？
